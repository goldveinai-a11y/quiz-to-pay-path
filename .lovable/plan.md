# Bible Quiz -> Paywall -> Bible Study App

## Рекомендация: один проект, один чат

Квиз и продукт делаем в **одном Lovable-проекте**. Причины:

- Данные квиза (ответы, цель, уровень) нужны продукту, чтобы построить персональный 30-дневный план — при двух проектах пришлось бы гонять их через API между базами.
- Один аккаунт/логин, одна база подписок: после оплаты пользователь просто попадает в `/app` — без повторной авторизации и без склейки пользователей.
- Один вебхук оплаты, один источник правды по статусу триала/подписки.
- Один домен: `site.com/quiz` (воронка) и `site.com/app` (продукт). Домен подключим позже — сначала всё живёт на превью-URL.

Разделять стоит только если позже воронку захочется отдать перформанс-команде на отдельный быстрый лендинг. Тогда выносим квиз во второй проект и передаём результат в продукт по ссылке с токеном. Начинать так не нужно.

## Порядок сборки (по шагам, отдельными задачами в чате)

Один проект — но не одна гигантская задача. Строим последовательно:

**Шаг 1. Скелет и дизайн**
Mobile-first дизайн-система под Bible-тематику, роутинг: `/quiz`, `/paywall`, `/plan`, `/app`, `/auth`.

**Шаг 2. Квиз-воронка** (механика как в примере stylix)
- Пошаговые экраны с одним вопросом на экран, прогресс-бар, свайп/тап-переходы.
- Ветвление по `?mode=` и сохранение UTM/campaign_id/adset_id/ad_id в сессию для последующей атрибуции.
- Промежуточные «social proof» и «loading/analysis» экраны перед результатом.
- Ответы хранятся локально до логина, затем привязываются к аккаунту.

**Шаг 3. Бэкенд (Lovable Cloud)**
Таблицы: `profiles`, `quiz_responses`, `plans`, `plan_days`, `progress`, `subscriptions`. RLS: каждый видит только своё. Атрибуция пишется в `quiz_responses`.

**Шаг 4. Аккаунты**
Email+пароль и Google. Логин запрашивается на переходе квиз → пейволл (стандарт для таких воронок: email до оплаты).

**Шаг 5. Пейволл и оплата (триал → подписка)**
Персонализированный экран результата, планы (недельный/месячный/годовой) с триалом, таймер/скидка. Платёжный провайдер подключаем встроенной интеграцией Lovable — перед этим прогоняю проверку соответствия продукта и рекомендую провайдера. Доступ к продукту открывается по статусу подписки из вебхука, не по редиректу.

**Шаг 6. 30-Day Bible Plan**
Генерация плана из ответов квиза: 30 дней, каждый — отрывок, короткое размышление, вопрос для рефлексии. Экран дня, отметка «выполнено», стрик.

**Шаг 7. Продукт (Bible study tool)**
Главный экран (пришлите hero-референс — соберу по нему), чтение, заметки/подсветки, прогресс, настройки и управление подпиской.

## Технические детали

- Стек: TanStack Start + React + Tailwind, Lovable Cloud (Postgres + Auth) на бэкенде.
- Гейт доступа: маршруты продукта под `_authenticated`, внутри — проверка активной подписки; отсутствие подписки → редирект на `/paywall`.
- Статус подписки обновляется вебхуком провайдера в таблицу `subscriptions`; фронт никогда не решает сам, оплачено ли.
- Квиз работает без логина (быстрее воронка), ответы летят в базу анонимной сессией и переносятся на аккаунт при регистрации.
- Метки рекламы прокидываются через все шаги, чтобы в базе была связка «клик → ответ → оплата».

## Что нужно от вас перед стартом

- Hero-референс продукта и, если есть, референсы экранов квиза.
- Страна регистрации бизнеса (для выбора платёжного провайдера и налогов).
- Цены и длительность триала.
