# Баг «мёртвых кликов» на первом вопросе квиза

## Симптом
На `/quiz` (первый вопрос, gender) клики в первые ~1–2 секунды после загрузки не срабатывают. После 2+ секунд — работают. Это единственный экран с полной загрузкой страницы, остальные 20 вопросов — SPA-переходы. На мобильном трафике это даёт наибольший провал воронки.

## Шаг 1 — Подтвердить причину (не гадать)
Есть подозрительное место: `src/routes/quiz.tsx` имеет gate `if (!hydrated) return <пустой экран>` — вопросы должны рисоваться только после загрузки localStorage. Значит либо gate не работает так, как ожидается (SSR/prerender рисует вопросы раньше), либо клики теряются на уровне гидрации React, либо дело в переходе с лендинга.

Playwright-тест на мобильном viewport с замедленным CPU/сетью:
- замерить время от первой отрисовки вопроса до момента, когда клик реально срабатывает (окно «мёртвых кликов»)
- проверить, рендерится ли вопрос до завершения гидрации (преререндер без JS)
- проверить, нет ли задержки из-за `setTimeout(onNext, 170)` и логики `selectSingle`

## Шаг 2 — Исправление (по результатам замера)
В зависимости от подтверждённой причины:

- **Если вопрос виден до гидрации**: блокировать взаимодействие до готовности JS — после гидрации экран становится кликабельным мгновенно; до этого показывать состояние загрузки вместо мёртвых кнопок (никаких кликов «в пустоту»).
- **Если гидрация медленная**: уменьшить JS-бандл первого экрана — отрезать тяжёлые зависимости продукта/оплаты от бандла квиза (lazy-импорты), чтобы время до интерактивности на 4G сократилось до минимума.
- **Если тормозит именно навигация landing → quiz (полная загрузка страницы)**: предзагружать ассеты `/quiz` с лендинга — `<link rel="prefetch">` на чанк квиза или router preload при маунте лендинга, чтобы после тапа по Start страница quiz приходила из кэша, а не с сервера.
- **Страховка в любом случае**: убрать задержку `setTimeout(170ms)` при авто-переходе либо сделать переход по `onPointerDown`-эквиваленту, чтобы быстрый тап не терялся.
- Убедиться, что состояние «ещё не готово» визуально отличается от «готово» — пользователь не должен видеть кликабельные с виду кнопки, которые не работают.

## Шаг 3 — Проверка
Повторить Playwright-тест: клик в первую секунду после загрузки должен срабатывать (или UI честно показывает загрузку). Прогнать на мобильном viewport с троттлингом, проверить, что остальные шаги квиза не сломались.

## Технические детали
- Файлы: `src/routes/quiz.tsx`, `src/components/quiz/StepRenderer.tsx`, возможно `src/lib/quiz/store.ts`, `vite.config.ts` (code splitting).
- Не трогаем логику ответов, аналитику и контент шагов — только механику готовности UI к клику.
